# 第四阶段：能力短板

从高级前端面试官的角度看，这个仓库能证明你知道通话状态不能散落在组件里，也能证明你知道 WebSocket 不是业务恰好一次。它还不能证明你已经把这些想法接到一条真实呼叫链上，也不能证明线上结果。

下面按“面试时会不会伤你”排序。

## 1. 不要过度包装的部分

这些是正常业务或常规脚手架。可以提一句，不要放进亮点第一条。

| 内容 | 理由 |
| --- | --- |
| 软电话键盘、主题、侧栏、检查器 | 展示和快捷键。时长用时间戳是好习惯，但只在 `MachineView` |
| `CallControls` / `StatusBadge` | 按状态渲染按钮。测试只断言来电文案 |
| React/Vue 示例组件 | 各一个文件，没有第二套业务 |
| tsup、Changesets、ESLint、CI 四步 | 合格的库工程，不是架构难点 |
| 状态机微基准约 5.14e6 ops/s | 纯函数本来就便宜。没有优化前的基线，不能写“性能提升” |
| 号码正则、DTMF 正则、并发上限 | 参数校验，不是容量系统设计 |

## 2. 有架构深度、但缺少验证的部分

| 设计 | 已有证据 | 缺的验证 |
| --- | --- | --- |
| 终态不可逆 | 状态机单测一条 | acquire 中途挂断、双 messageId 接通 |
| ResourceScope | 销毁后计数和晚到事件 | destroy 插在 init 的 await 中间 |
| 命令队列 | 无 | 失败后续跑、挂断排队时的状态时刻 |
| 不重放非幂等命令 | 一条抛错测试 | 超时、迟到响应、退避、满 1000 的淘汰 |
| iframe 三重校验 | 无 | 错误 origin / source 的单测 |
| 浏览器媒体 | 源码有 stop | jsdom 或真机都没有覆盖 `BrowserMediaManager` |
| React 订阅 | 无 | effect 前后的更新、卸载是否退订 |

优先补测试，不要先补概念。面试官要你白板讲竞态时，你可以说“这条有测试，那条我只读过代码”。这个区分本身是加分项。

## 3. 术语和实现不符的地方

不要在简历或口述里使用这些句子：

| 说法 | 实际情况 |
| --- | --- |
| 使用 XState / actor | ADR 说以后再考虑。依赖里没有 |
| `useSyncExternalStore` | `useState` + `useEffect` |
| `replaceTrack` 切换麦克风 | 没有调用 |
| `getStats`、MOS、抖动窗口 | `QualitySample` 未被引用 |
| Core 已集成心跳和自动重连 | `ConnectionManager` 未被 SDK 调用 |
| 重连后按 sequence 合并快照 | 没有快照 API |
| `ending` 状态表示正在挂断 | 没有迁移能进入 `ending` |
| 统一错误事件 | `SdkEvents` 有 `error`，没有任何 `emit` |
| `network-error` | 没有任何赋值；`FAIL` 总是 `signaling-error` |
| 代际 generation 会换新 scope | 字段从不替换 |
| token 注入传输层 | `getAccessToken` 的返回值被丢弃 |
| 转接 / 会议已完成 | `transfer` 只 send；没有会议状态 |
| 去重 LRU 上限 1000 | ConnectionManager 是 FIFO 淘汰 1000；SDK 那套无上限 |
| 恰好一次投递 | 代码特意避免这个承诺 |
| 微前端已落地 | 没有 qiankun/wujie，iframe 没有页面 |

旧的 `docs/interview/interview.md` 曾经把其中几条写成了参考答案。那份文件已改成索引，不要背删除前的版本。

## 4. 缺少文档的设计决定

源码里有行为，ADR 没写清楚，追问时只能靠你当场推：

- 为什么 `hangup` 的终态写在队列任务内部，而不是在 `hangup()` 进入时同步写。注释只说“本地意图优先”，没说队列忙的时候并不优先。
- 为什么远端事件不进 `enqueue`。
- 为什么振铃超时不在 `active` 时清除，以及为什么跳过列表没有 `holding`。
- 为什么 `dial` 先 `createCall` 再 `send`。这更像缺陷，不像决策。你需要准备“我会怎么补”，而不是把它讲成两阶段提交。
- 为什么 React 卸载销毁 SDK，Vue 卸载不销毁。
- 为什么静音不发信令。可能是合理的本地轨道开关，但没有任何注释。
- 为什么保持失败会把整通呼叫打成 `failed`，而不是回到 `active`。

已有 ADR 001 到 006，讲 XState、不可复活、依赖注入、不重放、UI 可选、SIP 边界。这些可以引用。引用时带上“实现到了哪一步”。

## 5. 值得补的测试和测量

按收益排序：

1. **会话竞态测试**（故事 1、6）  
   acquire 中途 hangup；两个 messageId 的接通；hold 未完成时 hangup 的发送顺序；send 失败后的 connecting 会话。

2. **超时测试**  
   ringing 超时进入 ended；active 之后定时器不再把 holding 打爆；incoming 是否也应该有超时。现在只有呼出登记了定时器。

3. **ConnectionManager 契约**  
   固定随机数后的退避次数；请求超时后的响应；abort；1001 条消息后最旧 id 再次出现。

4. **iframe 测试**  
   错误 origin、错误 source、错误协议、超时、destroy。jsdom 可以做。

5. **绑定测试**  
   订阅、退订、Provider 卸载调用 destroy 一次。

6. **包体积**  
   对 `packages/*/dist` 做一次 gzip，记下命令和日期。没有对照就不要写百分比。

7. **浏览器媒体**  
   在真机或带 fake device 的浏览器里确认 `track.stop` 会灭掉指示灯。jsdom 证明不了这个。

8. **E2E 故障开关**  
   至少一条：打开重复消息仍能到 active；打开拒麦后进入 failed。并把 `pnpm test:e2e` 放进 CI 或说明为什么不放。

压力测试若要升级，用浏览器堆快照比较 destroy 前后的 `MediaStreamTrack` 和 `WebSocket` 实例数。现有 100 次循环保留即可，口述时主动限定它的断言范围。

## 6. 追问里最容易露馅的点

按危险程度：

1. **“画一下拨号失败的时序。”**  
   你如果只背 happy path，会漏掉 createCall 已经插入 Map。面试官接着问并发名额，这条幽灵会话会把后面的拨号挡掉。

2. **“ConnectionManager 和 SDK 谁调用谁？”**  
   答“SDK 用它重连”就和仓库不符。正确说法是：策略写在连接层，适配器还没写。

3. **“挂断是同步的吗？”**  
   队列空闲时，终态在发送之前写入。队列里还有 hold/accept 时，要等前一个任务。

4. **“乱序会不会先振铃再接通？”**  
   不会重排。先到的接通直接 active，旧振铃丢弃。

5. **“React 18 并发下订阅安全吗？”**  
   现在不安全到 external store 那个程度。承认并说明通话数很小，是唯一站得住的答法。

6. **“100 次测试证明没有泄漏吗？”**  
   只证明四个诊断字段。继续坚称无泄漏会被追问堆快照工具。

7. **“token 放在哪？”**  
   宿主函数返回后，Core 没有字段保存它。不要说已经做了短期凭证下发。

8. **“转接成功的标志是什么？”**  
   Mock send 的 Promise 完成。会话状态不变。没有成功事件。

9. **“个人贡献？”**  
   只有一次提交。含糊地说“我们团队”或全说“我独立设计了每一行”都危险。按事实选择，并准备讲两个你亲手发现的缺陷：拨号失败不回滚，holding 上的拨号超时会抛错。

10. **“如果线上已经接通，本地挂断丢了？”**  
    仓库没有补偿查询。你要说出这个未知，而不是说终态规则已经和计费一致。

## 7. 改进顺序

**本周就够用于面试的**

- 把故事 1 的 5 分钟稿讲熟，尤其是队列和双接通。
- 准备一张纸：已实现 / 有缺陷 / 未实现。面试开始就用这张边界，而不是等被问倒。
- 确认个人贡献的说法，和提交作者 `omencao` 一致。

**下一轮代码，按面试收益**

1. `dial` 的 send 失败把会话打成 `failed` 或撤销。
2. 进入 `active` 时取消振铃超时。
3. `applyRemote` 的错误不要变成未处理拒绝；双接通只 acquire 一次。
4. 给上面三条补测试。
5. 写一个 50 行的 `ConnectionManager` 到 `SignalingTransport` 适配器，即使底层仍是 fake socket，也能证明接线方式。

**不要为了简历先做的**

- 引入 XState。
- 为了口述去接一个没有环境的 SIP 服务，再把未测通的代码讲成已上线。
- 把基准包装成性能优化项目。
