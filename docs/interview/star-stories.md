# STAR 技术故事

> 以下均为本次新建项目的可验证工程实践，不是对公司线上收益的陈述。

## 1. 接通与挂断竞态

**S**：控制指令和服务端信令异步到达。**T**：防止挂断后的会话被接通事件复活。**A**：本地 hangup 同步进入终态，所有远端事件统一经过状态机；终态转换幂等，并加入并发测试。**R**：测试可稳定复现并证明晚到 REMOTE_ACCEPTED 被忽略；真实服务端一致性仍需重连快照核对。

## 2. SDK 销毁时异步任务仍在运行

**S**：鉴权、媒体和信令请求可能晚于组件卸载完成。**T**：避免幽灵回调和资源泄漏。**A**：用 ResourceScope 统一持有 AbortController、订阅和 timer，回调同时检查作用域代际。**R**：100 次创建/销毁后诊断计数归零，测试覆盖 late signal。

## 3. WebSocket 可靠性边界

**S**：断网时盲目重放拨号会造成重复外呼。**T**：恢复连接但不破坏业务一致性。**A**：连接层实现 full-jitter backoff、关联请求、去重，只允许显式 replay-safe 消息排队。**R**：不安全命令离线时明确失败，可通过测试验证；服务端状态同步仍是集成前置条件。

## 4. 多框架 SDK 边界

**S**：CRM 宿主可能使用 React、Vue、原生或 iframe。**T**：避免核心绑定单一框架。**A**：Headless Core + ports/adapters，框架包仅把外部 store 投影为各自响应式模型，React/Vue 保持 peer dependency。**R**：同一 Core 可被两套类型检查通过的宿主示例消费。

## 5. Mock 可信度

**S**：无 PBX 环境仍要演示，但不能伪装成真实 SIP。**T**：让 UI 演示与生产架构使用同一路径。**A**：Mock 只替换 Transport/Media，状态机、Facade、事件流完全真实，并提供延迟、重复、乱序、掉线、权限拒绝注入。**R**：Playground 可离线跑完整链路，能力矩阵明确标记真实 SIP/ICE/Stats 尚未验证。
